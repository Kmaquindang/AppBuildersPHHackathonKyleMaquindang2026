- Oct 9, 6:24 PM: Encrypted rooms (commits 310ac08, 8131273). Each room has a spoken label (not secret) and a random 256-bit key shared by QR code (CoreImage) or a join string (`PASA1.<label>.<creator>.<key>`). Protocol v2: a clear routing header (version, id, room tag, origin, destination, ttl, hops) and a ChaCha20-Poly1305 sealed payload (CryptoKit); the room tag and sealing key come from HKDF-SHA256 of the room key, and the header is bound as associated data so relays can change only ttl and hops. Everything a device writes is sealed before it is sent or queued. Other rooms' packets are relayed unchanged and never shown or stored (at most 50 in the outbox, for an hour), and another room's `@pasa` ask passes through an AI Mac instead of stopping there. Per-room folders for chat and team memory, per-room clear watermark, per-room admins by device id with the creator pinned; the AI grounds only on the active room. Existing data, admins and the clear watermark migrate into a Default room with a public key (old files kept as `.bak`). First-run and Settings room picker (Default, create, join by paste), QR and copy, switch and leave; per-room export and import.
